## 2. The catalogue load (SQL)

Supabase → project `ctp-core` (`hkzmydowyiajkbakxfkj`) → **SQL Editor** → paste
the whole of `server/0046_multicat_codes.sql` → Run.

- It is one transaction. If any of the 155 Multicat codes would collide with a
  different part, or would end up with no part, it **raises and changes nothing**.
- It is idempotent: running it twice is harmless.
- The final SELECT should show `legacy_aliases 154 · costs_19oct 155 ·
  prices_19oct 151 · zoho_linked 155`, and `active_still_ctp_coded` 1–2 (the two
  flagged parts below).

What it does: renames every part's `sku` to its Multicat code (= Zoho SKU), keeps
the old `CTP-xxx` code as a searchable "CTP legacy" cross-reference, sets name /
landed cost / list price from Zoho+Multicat, adds CAB001, and creates the
`zoho_item` + `zoho_sync_run` tables. Part ids do not change: orders, photos and
diagram markers stay attached. The stock ledger is not touched.

Parts that need a Multicat fix (left as they are, flagged in `notes`):
- `CTP-TBX-002-R` Side Toolbox Cover R/H: its code 5407025-B45 collides with the L/H cover.
- `CTP-CBY-002-C` Cab Front Panel Inner Board: it shares 5300010-H02-DQ with Front Wall Welding.

Set to match Zoho: `CTP-STP-005-R`, `CTP-CBY-001-C` and `CTP-CBY-004-C` become
discontinued. `CTP-TBX-004-R` and `CTP-DOR-022-R` become superseded by the
"L/H or R/H" item.

5302021-B45-G keep their current CTP list price until the first Zoho pull.

## 3. Zoho Self Client (about 5 minutes)

1. Open the API console for **your Zoho data centre**. The domain is the one
   in your Zoho Books/Inventory URL: `api-console.zoho.com` (US),
   `.eu` (EU), `.in`, `.com.au`, and so on.
2. **Add Client → Self Client → Create.** Copy the Client ID and Client Secret.
3. **Generate Code** tab. Scope (Inventory, read-only):
   `ZohoInventory.items.READ,ZohoInventory.settings.READ`
   (if you use Books instead: `ZohoBooks.settings.READ,ZohoBooks.items.READ`).
   Duration 10 minutes. Copy the code.
4. Exchange it for a refresh token, within the 10 minutes, from any terminal.
   Put **your** values in place of the capitals:
   ```
   curl -X POST "https://accounts.zoho.com/oauth/v2/token" -d "grant_type=authorization_code" -d "client_id=CLIENT_ID" -d "client_secret=CLIENT_SECRET" -d "code=THE_CODE"
   ```
   (Use the same data-centre domain as in step 1.) Copy `refresh_token` from
   the reply. It does not expire unless revoked. Do not paste it into chat or email.
5. Organisation ID: in Zoho Inventory go to Settings → Organization Profile.

## 6. First sync

Settings → **Zoho** → **Check Zoho**. This changes nothing in CTP Core. It lists
what would change (names, list prices, landed costs) and any Zoho item not in
CTP Core. If it looks right, press **Pull & apply**. Zoho stock shows per item in
the same tab. It stays 0 until Michelle's Supalift bills and Hermans invoices are
in Zoho. Press Check again after that.

Zoho stock is a mirror. It is **never** written into CTP Core's own stock
ledger, so the two can be compared but never double-counted.

## 7. Desktop app (Tauri) 1.1.0

The desktop migration (`0025`, user_version 24) renames parts **locally before
the next cloud pull**. The pull matches parts by SKU, so without it every
desktop would get 155 duplicate parts. **Install 1.1.0 before using an old
desktop build against the renamed cloud data.**

One time per build machine:
```
install-prereqs.bat            (Rust via rustup + MSVC C++ Build Tools; then open a NEW terminal)
```
Build:
```
cd app
npm ci
npm run tauri build
```
Installers land in `app/src-tauri/target/release/bundle/msi/` and `.../nsis/`.
`app/public/assets` (the local image library) is not in git; pull it first with
`node tools/pull_assets.mjs` if the desktop should show photos offline.
