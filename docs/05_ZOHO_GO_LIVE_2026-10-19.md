## 2. The catalogue load (SQL)

Supabase → project `ctp-core` (`hkzmydowyiajkbakxfkj`) → **SQL Editor** → paste
the whole of `server/0046_multicat_codes.sql` → Run.

- It is one transaction. If any of the 155 Multicat codes would collide with a
  different part, or would end up with no part, it **raises and changes nothing**.
- It is idempotent: running it twice is harmless.
- The final SELECT should show `legacy_aliases 154 · costs_19oct 155 ·
  prices_19oct 151 · zoho_linked 155`, and `active_still_ctp_coded` 1–2 (the two
  flagged parts below).

What it does: renames every part's `sku` to its Multicat code (= Zoho SKU), keeps
the old `CTP-xxx` code as a searchable "CTP legacy" cross-reference, sets name /
landed cost / list price from Zoho+Multicat, adds CAB001, and creates the
`zoho_item` + `zoho_sync_run` tables. Part ids do not change: orders, photos and
diagram markers stay attached. The stock ledger is not touched.

Set to match Zoho: `CTP-STP-005-R`, `CTP-CBY-001-C` and `CTP-CBY-004-C` become
discontinued. `CTP-TBX-004-R` and `CTP-DOR-022-R` become superseded by the

## 3. Zoho Self Client (about 5 minutes)

1. Open the API console for **your Zoho data centre**. The domain is the one
   in your Zoho Books/Inventory URL: `api-console.zoho.com` (US),
   `.eu` (EU), `.in`, `.com.au`, and so on.
2. **Add Client → Self Client → Create.** Copy the Client ID and Client Secret.
3. **Generate Code** tab. Paste this scope list (read items/stock + write
   contacts, invoices and bills; DELETE only so the live test can remove its
   own TEST records — it can be revoked afterwards):
   ```
   ZohoInventory.items.READ,ZohoInventory.settings.READ,ZohoInventory.contacts.CREATE,ZohoInventory.contacts.READ,ZohoInventory.contacts.UPDATE,ZohoInventory.contacts.DELETE,ZohoInventory.invoices.CREATE,ZohoInventory.invoices.READ,ZohoInventory.invoices.UPDATE,ZohoInventory.invoices.DELETE,ZohoInventory.bills.CREATE,ZohoInventory.bills.READ,ZohoInventory.bills.UPDATE,ZohoInventory.bills.DELETE,ZohoInventory.purchaseorders.CREATE,ZohoInventory.purchaseorders.READ,ZohoInventory.purchaseorders.UPDATE
   ```
   Duration 10 minutes. Copy the code. (Zoho Books without Inventory? Tell
   Claude — the scopes become `ZohoBooks.*` and the API base changes.)
4. Exchange it for a refresh token, within the 10 minutes, from any terminal.
   Put **your** values in place of the capitals:
   ```
   curl -X POST "https://accounts.zoho.com/oauth/v2/token" -d "grant_type=authorization_code" -d "client_id=CLIENT_ID" -d "client_secret=CLIENT_SECRET" -d "code=THE_CODE"
   ```
   (Use the same data-centre domain as in step 1.) Copy `refresh_token` from
   the reply. It does not expire unless revoked. Do not paste it into chat or email.
5. Organisation ID: in Zoho Inventory go to Settings → Organization Profile.

what would change (names, list prices, landed costs) and any Zoho item not in
CTP Core. If it looks right, press **Pull & apply**. Zoho stock shows per item in
the same tab. It stays 0 until Michelle's Supalift bills and Hermans invoices are

Zoho stock is a mirror. It is **never** written into CTP Core's own stock
ledger, so the two can be compared but never double-counted.

## Write-back: what goes to Zoho, and when

| CTP Core act | Zoho document | Contact | Default |
|---|---|---|---|
| **invoice_order** (Issue invoice, after fulfil) | **Invoice**, number = CTP invoice no., reference `CTP-INV-<no>` | customer (Zoho contact type customer) | **always draft** |
| **post goods receipt** (desktop Receiving) | **Bill**, bill no. = supplier's invoice ref, reference `CTP-GRN-<no>` | supplier (Zoho contact type vendor) | **always draft** |

Not Zoho sales orders: CTP Core's own quote → confirmed → fulfilled flow is the
order, and a Zoho sales order on top would commit the same stock twice.
POs → Zoho purchase orders are phase 2.

- **Always draft — Michelle's standing rule.** Every invoice and bill CTP Core
  creates in Zoho is a draft; Michelle approves it in Zoho. The flag is in
  `zoho_config`, defaults to draft, has no toggle in the app, and only an admin
  can change it, from the SQL editor: `select set_zoho_draft_policy(true, true);`
- **Status comes back.** Zoho's status (Draft → Sent → Paid / Void, also
  Part-paid, Overdue, and "Deleted in Zoho") is read back onto each invoice and
  receipt: when the order desk opens (at most every 2 minutes) and with
  Settings → Zoho → **Refresh status from Zoho**. The order card shows
  "Zoho: Draft — awaiting accountant" until Michelle approves it. A document
  deleted in Zoho is flagged and never silently re-sent.
- **Go-live only.** Nothing invoiced/received before the go-live date is ever
  sent; turning sending on without a date is refused by the database.
- **Idempotent.** Zoho id stored on the CTP record; Zoho is searched for the
  `CTP-…` reference before creating, so a retry never duplicates.
- **Contacts** matched by stored Zoho id, then email, then VAT no., then exact
  name; created if none match (VAT no. written into the contact's notes).
- **Lines** by item code = Zoho SKU via the cached Zoho item id. An unlinked
  code blocks the whole document with the reason shown.
- **Visible.** The invoice toast and the receipt screen say "Sent to Zoho as
  draft …" or "NOT sent to Zoho: <reason>". Settings → Zoho lists everything
  waiting or failed, with **Send now**, and the full log.
- **Secrets live only in Supabase Edge Function secrets.** Not Vercel (the PWA
  is static files, anything given to it is public) and not a local .env (the
  desktop must never hold the Zoho client secret).
- **Desktop receipts** reach the cloud through `submit_goods_receipt()` — the
  record only, no stock movement in the cloud ledger.
